## Project state

**The backend is complete in simulation.** D0 and D1, the dashboard connection shell and recorded-run network viewer, now exist and are locally verified on macOS. Full Phase 0 still requires both owners to start it from a fresh checkout on their operating systems. Phases 1, 2, 3, 4a, 4b, 5a, 5b, **9 (adaptive routing, simulation only)** and the backend part of **10**, and the laptop side of Phase 6 ("6-prep"), are done on the backend side. **What remains is Dev's dashboard and firmware, and the joint hardware phases (6, 7, 8).** [docs/HANDOFF_FOR_DEV.md](HANDOFF_FOR_DEV.md) is the single document for Dev to review it all. The agreed project uses four ESP8266 NodeMCU boards. Hardware has not been purchased; no radio, USB, sensor or firmware exists, and no hardware test has been performed. The dashboard shows live connection/mode metadata and a separate recorded network viewer; live network state and controls are pending. The laptop side of the USB serial link exists (a serial line format, a `SerialGateway`, hardware mode) and has been run only against a fake node C. The running code is the backend under `backend/`: a status-only API, the protocol codec, and a four-node simulator with forwarding, retries, duplicate detection, HELLO discovery, link probes and bounded flooding, plus a controller that detects node and link failures, calculates routes with Dijkstra over measured links, installs them with versioned, acknowledged updates, and reroutes automatically, with controller-installed backup next hops that nodes switch to on their own (local failover). The simulation now also runs **live** inside the backend and is served to the dashboard through an HTTP/WebSocket API with presenter controls (Phase 5a). The controller sends node C a heartbeat; when it stops, C keeps the radio side working and holds what it would have sent up in a bounded buffer, which it replays when the controller returns (Phase 5b). Since Phase 6-prep the backend can also run in hardware mode on node C's USB serial port, with a numbered and acknowledged uplink so that even a one-second interruption loses nothing silently; this has been tested only against a fake C. Since Phase 9 the controller can choose routes by lowest delay (smoothed RTT) or highest reliability (probe delivery probability), with hysteresis, selectable by configuration and live API; since Phase 10 a run can be kept in a bounded SQLite history and exported as CSV. The firmware is not started. The dashboard shell and recorded graph are implemented; live network state, controls and history remain pending.
