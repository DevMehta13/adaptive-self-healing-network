# Current status

Last updated: 2026-10-13

## Project state

**Phase 0 is half done (the backend half exists; the dashboard half is Dev's and has not started). Phases 1, 2, 3, 4a and 4b are done on the backend side.** The agreed project uses four ESP8266 NodeMCU boards. Hardware has not been purchased; no radio, USB, sensor, dashboard, firmware or serial gateway exists, and no hardware test has been performed. The running code is the backend under `backend/`: a status-only API, the protocol codec, and a four-node simulator with forwarding, retries, duplicate detection, HELLO discovery, link probes and bounded flooding, plus a controller that detects node and link failures, calculates routes with Dijkstra over measured links, installs them with versioned, acknowledged updates, and reroutes automatically, with controller-installed backup next hops that nodes switch to on their own (local failover). The controller heartbeat and C buffering and replay (Phase 5), adaptive policies (Phase 9), and all dashboard wiring are not started.

    **Why, in terms of timers.** *Controller-only* and *T1* both wait for the same 3 s neighbor timeout, counted from the last HELLO (so 2.0 to 3.1 s after the stop with 1 s HELLOs and ±0.1 s jitter). T1 saves only what the controller needs after that: the report's trip to C and two install rounds, about 0.2 s; in the one-way failure it saves nothing measurable, because A learns B is one-way only after *B* has timed A out (3 s) and sent its next HELLO. *T2* does not wait for any timeout: it needs K = 3 failed sends to B. A sends HELLO (1/s) and PROBE (1/s) to B plus forwarded floods and DATA, so three failures accumulate in roughly 0.1 to 1 s depending on traffic at that moment. The controller's route is also confirmed sooner in T1 + T2 because the node's failover report reaches it before its own detection. The *first reading* on the backup is quantised by the reading interval and the 1 s ACK timeout: a reading created at the failure retries at +1 s, +2 s; so "first send" is 1.0 s for T2, about 3.0 s otherwise, and the delivery gap follows it. That is why the gain in the gap is smaller than the gain in the switch with 2 s readings, and why a faster reading interval shows more of it. T1 alone is therefore a modest improvement on a relay failure and none on a one-way failure.
